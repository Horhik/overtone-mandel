# AGENTS.md — Overtone Mandelbrot

Множество Мандельброта, которым управляет обертональное пение. C99, raylib, miniaudio (идёт внутри raylib). Цели: Android (шаблон Raymob) и Linux-десктоп для отладки.

## Управление голосом

| Голос | Параметр в коде | Что делает |
|---|---|---|
| Основной тон `f0` относительно базового тона `f0Base` (ползунок внизу) | `zoomRate` | выше базы — приближение, ниже — отдаление; скорость растёт с расстоянием в полутонах (мёртвая зона `DEAD_SEMI`, полная скорость через `FULL_SEMI`) |
| Частота выделенного обертона, лог-шкала `OT_LO..OT_HI` → полный круг | `otAngle` | направление движения (500 Гц — вверх, против часовой) |
| Выделенность обертона над соседями, дБ, `PROM_LO..PROM_HI` | `promS` | скорость движения |
| Тишина / нет тона | — | стоп |

Сцены (`SCENES[]` в `main.c`): drift, dive + colour, организм ×3 пресета (`ORG_PRESETS`: мандалы / клетки / сосуды), newton, apollonian. `M` — следующая сцена, `A` — авто-шоу: каждые `SCENE_SEC` (75 с) плавный переход за `FADE_SEC` (6 с) к следующей из `SHOW[]` (обе сцены рисуются в `rt`/`rtPrev` и смешиваются). В `SHOW` две мандельбротовские сцены не стоят рядом: у них одна опорная орбита. `H` или `F11` — спрятать интерфейс и курсор, остаётся только картинка (для зрителей / трансляции). Окружение: `SCENE=<n>`, `AUTO=1`, `SCENE_SEC=…`, `HIDE_UI=1`.

«Живые» сцены (организм, newton, apollonian) делят управление: f0 — `slice` (у newton это релаксация метода, у apollonian — масштаб инверсии), обертон — мутация `C`, громкость/доли — пульс, вращение, течение. Шейдеры с общими uniform'ами (`LIVE_UNIFORMS`).
- **newton** — бассейны релаксированного метода Ньютона для кубического многочлена, корни плавают по кругу и «дышат», обертон тянет один корень; границы бассейнов светятся, вокруг корней — кольца-«лепестки».
- **apollonian** — свёртка + инверсия в круге (семейство аполлониевой сетки): вложенные круги, тонкие линии по оценке расстояния.

Режимы по кругу (исторически; теперь это часть сцен):
- **drift** — обертон задаёт направление движения (таблица выше);
- **dive + colour** — центр прибит к точке из `DIVES[]` (точки Мисюревича, уточнены Ньютоном в 50 знаков: морской конёк, слоны, четверная спираль, скипетр, дендрит c = i), f0 относительно базы — зум, обертон — сдвиг палитры по кругу.

- **organism** — 2D-срез 3D Kaliset (`p = |p|/(p·p) + C`, шейдер `FS_ORG`): f0 относительно базы — движение среза по третьему измерению (`SLICE_MAX`), обертон ведёт C по пространству параметров (`MUT_SPEED`, не дальше `MUT_R` от `ORG_C0`), форма остаётся мутировавшей. Плюс медленная жидкая деформация и вращение. Окраска: прожилки (близкие длины соседних итераций), мембраны (orbit trap по z), тёмные тела клеток там, где орбита улетает. Глубокие итерации взвешены вниз — иначе мелкая «крупка». Настройка: `ORG_C=x,y,z`, `ORG_ZOOM=…` в окружении. Срез и мутация копятся без ограничений, но в шейдер идут через `sin()` (маятник: `SLICE_C ± SLICE_A`, `C0 ± MUT_R`) — иначе за долгую музыку срез уезжал за ~±1.5, где узор пустеет и остаётся только мигание. Движение: 3D-вращение среза и скорость течения растут с громкостью, атаки звука (`envFast` vs `envSlow`) дают толчок `kick` — рывок поворота и «вдох» масштаба. `ORG_SLICE=…` — стартовый срез (отладка).

Drift: если центр экрана во внутренности множества (опорная орбита не убегает) дольше 2 с — автоматически всплытие, чтобы не висеть в чёрном с одной пульсацией.

Ползунок базы: крайнее левое положение — 0 Гц, тогда любой голос считается «выше базы» (приближение / вперёд по срезам), скорость задаёт громкость (`VoiceDrive`). Стрелка ↓ ниже `F0_LO` тоже ставит 0.

**Beat** (`beat.c`): огибающая атак (рост лог-энергии, низы ×4) с шагом 512 сэмплов → автокорреляция по 60–180 BPM с мягким приоритетом около 120 → гистерезис темпа → фаза гребёнкой по последним атакам. Захват ~6 с. Пульс `exp(-phase·7)` включается, только когда темп уверенный (`conf`), добавляется к `uPulse` и даёт лёгкий «удар» зумом. Сила — ползунок под кнопками / `[` `]` / `BEAT=…` (0..1.5). Проверено на синтетике 95 и 128 BPM: ошибка темпа < 0.2 BPM, фазы ~0.03 доли.

**Physarum** (`physarum.c`, поверх любого режима, `P` / кнопка / `PHYSARUM=1`): модель Джонса на CPU, 60k агентов, сетка 480×270 (тор), ~2 мс/шаг на ядре. След: частичное размытие + затухание, яркость нормирована на средний след (иначе либо пусто, либо всё залито). Рисуется аддитивно поверх фрактала. Звук: громкость → скорость и отложение, обертон → угол сенсоров 25–65° (узкий — прожилки и сосуды, широкий — соты-клетки), доли и атаки → часть агентов получает случайный курс. Старт обязательно случайный: симметричный (кольцо) схлопывается в несколько прямых стволов. Хаос: самая частая нота за ~1 с (сильнейший пик спектра `peakFreq`, гистограмма по нотам с весом громкости) → `chaosU` 0..1 между `CHAOS_NOTE_LO..HI` (C2..C7): низкая — длинные сенсоры, крупные спокойные клетки, большие вихри; высокая — короткие сенсоры, сильное блуждание, до трети «диких» агентов (без чутья, быстрые, яркий след) и мелкие частые вихри. Сила — `CHAOS_AMT`. На кнопке: нота и полоска хаоса.

Цикл погружений (оба режима): на пределе точности (~2e-13) через `LIMIT_HOLD` с включается всплытие — любой голос только отдаляет (`ASCENT_MIN..MAX`). В режиме dive по пути центр плавно едет к следующей точке (`ASCENT_PAN`, скорость пропорциональна масштабу), и когда масштаб ≥ `ASCENT_TOP` и центр на месте — снова погружение. По кругу.

Палитра: тёмный лес (чёрно-зелёный, хвоя, мох, бирюза) + светящиеся нити по границе (оценка расстояния `der` в шейдере, в пикселях). `uPulse` — громкость: нити и фон «дышат». `uGlow` — сила обертона: нити от лишайника к углям. Виньетка по краям.

Отладка: `DIVE=<n>` — стартовая точка, `VOICE_LOOP=1` — крутить `VOICE_WAV` по кругу.

Обертон захватывается по частоте в Гц (не по номеру гармоники — октавные ошибки f0 его не сдвигают) и меняется на другой, только если захваченный не встречался `OT_SWITCH` с. Направление/цвет сглаживается как вектор (`DIR_RATE`, медленнее при слабом обертоне), скорость — `VEL_RATE`. На компасе: оранжевая стрелка — сглаженное направление, тонкая белая линия — сырое.

Панель спектра (справа внизу): бледная кривая — спектр 0–4 кГц, столбики — гармоники f0·n (подписаны номерами), оранжевый — самый выделенный обертон с подписью `H<n>  <Гц>`; подсвеченная полоса — где ищется обертон (450–4000 Гц). Данные — `spec[]`, `harmDb[]`, `otN` в `VoiceInfo`.

Ползунок базового тона: тянуть мышью / пальцем, стрелки ↑/↓ — на полутон, `F0_BASE=…` в окружении — стартовое значение. Двойной тап / `R` — сброс. Удержание / пробел — отдаление. Все константы — `#define` в начале `main.c`.

## Сборка и проверка

```sh
# Android
./gradlew assembleDebug                      # нужен SDK + NDK; APK в app/build/outputs/apk/debug/
nix develop -c ./gradlew assembleDebug       # NixOS: JDK 17, SDK 34, NDK 26.1.10909125, CMake 3.30.3 из flake.nix

# Desktop
cmake -S desktop -B desktop/build && cmake --build desktop/build -j
./desktop/build/overtone_mandel              # микрофон
nix develop .#desktop -c sh -c "cmake -S desktop -B desktop/build -DGLFW_BUILD_WAYLAND=OFF && cmake --build desktop/build -j"   # NixOS, X11/XWayland

# Без микрофона и экрана (CI, контейнер)
VOICE_WAV=desktop/voice_test.wav SHOT_DIR=/tmp/shots LIBGL_ALWAYS_SOFTWARE=1 \
  xvfb-run -a -s "-screen 0 1280x720x24" ./desktop/build/overtone_mandel
#   SHOT_DIR: скриншот каждые 0.5 с + строка "SHOT ..." в логе (f0, обертон, зум, центр)
#   TEST_SCALE=1e-12: стартовать сразу на глубине (проверка точности)

# Только анализ голоса
python3 tools/synth_overtone.py && gcc -O2 tools/voice_cli.c app/src/main/cpp/voice.c -lm -o /tmp/vc && /tmp/vc
```

Ожидаемо на синтетике: дрон 120 Гц определяется как 120 (не 360/480), выделенность обертона 12–21 дБ, у простой гласной около 6 дБ.

## Как устроено (неочевидное)

- **Тон (`voice.c`).** Сильный обертон сбивает YIN на свой период. Поэтому собираются все минимумы YIN, каждый кандидат оценивается контрастом гармонической гребёнки в спектре (пик против середины между гармониками), и берётся самая низкая частота в пределах 3 дБ от лучшей оценки. Субоктавы проигрывают по контрасту, обертоны — нет, поэтому побеждает настоящий f0.
- **Обертон.** Среди гармоник в полосе 450–4000 Гц ищется та, что сильнее всех выделяется над медианой соседей ±3. Форманты гласных широкие, обертон пения узкий. Номер гармоники уточняется центроидом мощности.
- **Глубокий зум.** Опорная орбита считается в центре экрана в double на CPU и передаётся текстурой RGBA32F 1024×4. Шейдер считает во float только отклонение (perturbation) с перебазированием (rebasing) — так глитчи не нужно ловить отдельно. Предел около 2e-13 от масштаба: его ограничивает double опорной точки.
- **Шейдер** один, заголовок подставляется по `rlGetVersion()`: GLSL 100 / 300 es / 330.

## Подводные камни

- Перед `#include "external/miniaudio.h"` в `main.c` должен стоять тот же набор `MA_NO_*`, с которым raylib компилирует `raudio.c`. Иначе разъедется раскладка `ma_device`. При обновлении raylib сверить.
- На GLES `precision highp sampler2D` обязателен: по умолчанию `lowp`, и опорная орбита превращается в мусор.
- CMake нужен 3.30.3 (так в `app/build.gradle`): вендоренный raylib требует ≥ 3.25, 3.22.1 из Android SDK не подойдёт.
- `deps/raylib/README.md` нужен для сборки: raylib безусловно подключает CPack, а тот проверяет, что файл существует.
- raylib на Android линкует только `GLESv2`, функции ES 3.0 лежат в `GLESv3`. Поэтому он добавлен в `target_link_libraries` в `app/src/main/cpp/CMakeLists.txt`.
- NixOS: aapt2 из Maven не запустится, flake передаёт через `GRADLE_OPTS` `android.aapt2FromMavenOverride` на aapt2 из SDK. Путь в `/nix/store` машинный, поэтому не в `gradle.properties`.
- Raymob в `preBuild` переписывает имя пакета в Java и в `deps/raymob/*.c`, а после сборки возвращает обратно. Не коммитить эти файлы в промежуточном состоянии.
- Разрешение на микрофон спрашивается из C через JNI (`MicPermission`), захват стартует, когда разрешение выдано (опрос раз в секунду).
- `minSdk 24`: AAudio есть только с API 26, ниже miniaudio сама переключится на OpenSL ES.

- Десктоп собран и проверен на синтетическом пении, глубина до 1e12 рисуется чисто.

## Что можно сделать дальше

- Проверить на телефоне: задержку, производительность шейдера (`RENDER_SCALE`, `ITER_CAP`), уровни микрофона.

- Зум глубже 1e13: опорная орбита в произвольной точности (MPFR / свой bigfloat), дельты в float с экспонентой.
